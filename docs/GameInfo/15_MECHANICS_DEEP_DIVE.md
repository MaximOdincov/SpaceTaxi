# 15 — МЕХАНИКИ: ИДЕИ И РЕАЛИЗАЦИЯ (шпаргалка для защиты)

Как устроена каждая фича игры: замысел → реализация (формулы, классы,
приёмы) → файлы. Вопрос преподавателя «как сделано X?» → находишь секцию.

---

## 1. Ньютоновская гравитация

**Идея.** Корабль притягивается ко всем телам одновременно по закону
обратных квадратов — вокруг планет возникают настоящие орбиты, траектории
искривляются, а «качель» (гравитационный манёвр) получается сама собой.

**Реализация.** Собственный закон поверх физики Unity: у Rigidbody2D
гравитация выключена (`gravityScale = 0`), вместо неё в `FixedUpdate`
считается суммарное ускорение от каждого тела:

```
g тела = GravityParamK · радиус · массаМножитель      (K = 52000, удвоили прототип)
a      = min(g / d², 240)                              (кламп у поверхности)
```

Кламп 240 нужен, чтобы у самой поверхности ускорение не уходило в
бесконечность. Ускорение применяется напрямую к скорости — как интегратор
Эйлера. Тела регистрируются в общем поле (`Register/Unregister` в
`OnEnable/OnDisable`), расчёт — единая точка `GravityField.GetAccelerationAt`.

**Почему не физика Unity.** Встроенная гравитация — только постоянный
вектор (для платформеров). Нужна суперпозиция от N тел с квадратичным
затуханием — это свой код, физика Unity оставляет только коллизии.

**Файлы.** `Physics/GravityField.cs`, `Physics/ShipController.cs`,
`Physics/PhysicsConfig.cs` (все константы — ScriptableObject, баланс
правится без кода).

## 2. Управление: тяга вдоль вектора скорости

**Идея.** Нет ручного поворота (упрощение для «таксиста»): корабль всегда
стремится носом по движению, а игрок управляет ускорением относительно
вектора скорости.

**Реализация.** Каждый физический тик:
- **W** — ускорение 95 вдоль скорости (в посадочном кольце ×3.2 = 304);
- **S** — торможение: скорость пропорционально уменьшается на 115·dt (×3.2 в кольце);
- **A/D** — боковое ускорение 130 перпендикулярно скорости, «изгибает»
  траекторию; с капом угловой скорости 60°/с (медленный корабль не крутится
  «юлой» — ускорение ограничено: `min(StrafeAcc, v·60°)`).
- **MAXV = 330** — НЕ жёсткий кламп: при v ≥ 330 тяга просто не работает,
  но гравитация имеет право разогнать сильнее (физически честно).

Нос доворачивается к вектору скорости с плавностью 4/с через
`Rigidbody2D.MoveRotation` (писать поворот в transform нельзя — конфликт
с интерполяцией физики, из-за этого был джиттер).

**Файлы.** `Physics/ShipController.cs`, ввод — Input System ассет
`Settings/GameInput.inputactions` (карта «Ship»: W/ПРОБЕЛ/↑ — тяга,
S/↓ — тормоз, A/D/стрелки — ось стрейфа).

## 3. «Качель» — гравитационный манёвр

**Идея.** Награда за смелый пролёт рядом с планетой: вошёл в кольцо
влияния на высокой скорости — получил буст, как межпланетные зонды у Юпитера.

**Реализация.** У каждого тела кольцо `r·3.3 + 30`. Фиксируется ФРОНТ
события (вход в кольцо, а не нахождение в нём — иначе буст накручивался бы
каждый кадр). В момент входа: если скорость выше убегающей
`vEsc = √(2g/d)` — скорость умножается на 1.15. Вышел из кольца и вошёл
снова — можно получить ещё раз.

**Файлы.** `Physics/ShipController.cs` (блок качели в FixedUpdate).

---

## 4. Посадка: ретро-разворот, вертикаль, зум

**Идея.** Посадка как у Falcon 9: корабль разворачивается двигателями
вперёд и тормозит «посадочным прожигом», у поверхности выравнивается
вертикально. Это делает посадку зрелищной и читаемой.

**Реализация.** Три состояния ориентации носа:
1. обычно — по вектору скорости;
2. **S в посадочном кольце** (r + 90) → цель разворота = вектор скорости
   + 180° («двигателями вперёд»), флаг `LandingRetro`;
3. **финал** (до поверхности < 40 юнитов и v < 50) → нос строго от центра
   планеты (вертикаль).

Камера: при `LandingRetro` или стоянии на планете видимая высота
320 → 190 (планета «растёт»), после взлёта плавно возвращается.
**Касание**: v < 38 — посадка (снап на поверхность, скорость в ноль);
v ≥ 38 — урон `max(5, (v−38)·0.9)`; если HP > 0 после урона — корабль
сразу считается севшим (никаких отскоков и дребезга). Взлёт — W/ПРОБЕЛ,
импульс 85 от центра.

**Файлы.** `Physics/ShipController.cs` (UpdateHeading),
`Physics/LandingSystem.cs`, `Physics/CameraFollow.cs`.

## 5. Жар звезды

**Идея.** Звезда — территория риска: чем ближе к поверхности, тем быстрее
горит корпус.

**Реализация.** Жаровая зона радиуса `r·3.6`. Каждый физический тик — если
корабль в зоне: `k = 1 − (d − r)/(heat − r)` (0 на краю зоны, 1 у
поверхности), урон `k · 30 HP/с`. Касание поверхности звезды — мгновенная
гибель.

**Файлы.** `Physics/HullSystem.cs` (ApplyHeat), `World/Star.cs`.

---

## 6. Прочность, гибель, респавн

**Идея.** Единая точка правды по HP; UI и звук узнают об изменениях
событиями, а не опросом.

**Реализация.** `HullSystem.ApplyDamage` клампит HP и бросает события
`HpChanged`, `Died`, `ShipLost(reason)`, `Respawned` (на них подписаны HUD,
тосты, звук). HP = 0 → 0.6 с паузы → телепорт на планету старта
(угол спавна из уровня), HP и бак полные, активный заказ проваливается.

**Файлы.** `Physics/HullSystem.cs`.

---

## 7. Топливо и потеря корабля

**Идея.** Ресурсное давление без экономики: топливо тратится только на
двигатели, пустой бак — драма дрейфа.

**Реализация.** Расход 5.5 ед/с при любой зажатой тяге (W/S/A/D), только в
полёте. `Ship.Fuel` — свойство: при записи клампится и бросает
`FuelChanged` (HUD-сегменты). Бак = 0 → тяга и взлёт заблокированы,
баннер «ТОПЛИВО КОНЧИЛОСЬ», в бортовом компьютере появляется кнопка
«ОТКЛЮЧИТЬ КОРАБЛЬ» → `HullSystem.Abandon` (респавн без взрыва). Не нажал
и улетел за границу системы (2500, задаётся в уровне) — «ПОТЕРЯНА СВЯЗЬ»,
авто-отключение. Стоишь с пустым баком на планете без станции — та же кнопка.

**Файлы.** `Physics/Ship.cs`, `Physics/ShipController.cs`,
`Physics/HullSystem.cs`, `World/LevelAsset.cs` (WorldRadius).

## 8. Прогноз траектории (пунктир)

**Идея.** Главный навигационный инструмент: линия показывает, куда тебя
унесёт гравитация, если ничего не делать.

**Реализация.** Та же формула гравитации, что и в полёте (одна точка
правды — `GetAccelerationAt`), шаг 1/120 с, горизонт 2.5 с, обрыв при
столкновении с телом. Рендер — пул из 64 спрайтов-чёрточек: каждая ставится
через N пройденных юнитов и поворачивается по касательной. Стабильность:
направление сглаживается к вектору скорости (не к носу), шаг пунктира
меняется плавно, прозрачность привязана к номеру чёрточки. На посадке
(ретро/финал) и при v < 30 линия скрыта.

**Файлы.** `Physics/TrajectoryPredictor.cs`.

## 9. Мир из данных + редактор уровня

**Идея.** Уровень — ДАННЫЕ (ScriptableObject), а не сцена: геймплей
строит мир кодом при старте, редактор уровня пишет в те же данные.
Дизайнер меняет уровень, не трогая код и сцену.

**Реализация.** `LevelAsset`: список тел (тип, позиция, радиус, масса,
жар, overrides колец, визуал-настройки, флаг станции), граница мира,
планета старта и угол спавна. `WorldBuilder` инстанцирует префабы и
применяет данные. Редактор — EditorWindow (`Space Taxi → Level Editor`) +
гизмо в Scene View (кольца посадки/качели, жар, спавн, дистанции, рамка
камеры, граница), перетаскивание со snap 10 и Undo, живая валидация
(пересечения, жар у спавна, нормы радиусов), зонд гравитации по Ctrl,
превью гравиполя и траектории спавна.

**Файлы.** `World/LevelAsset.cs`, `World/WorldBuilder.cs`,
`Editor/LevelEditorWindow.cs`, `Editor/LevelEditorSceneView.cs`.

## 10. Заказы

**Идея.** Полный цикл такси: входящие предложения → один активный заказ →
посадка на А (взял) → посадка на Б (сдал). Правила гарантируются кодом.

**Реализация.** `OrderService`: поток карточек (каждая живёт 60 с, новая
каждые 15–30 с, максимум 4; при активном заказе список скрыт — второй
взять невозможно по определению `Accept`). Посадка — единственная точка
смены состояния: событие `LandingSystem.ShipLanded` → сверка с планетой А
(пассажир на борту) / Б (доставка, счётчик+1). Гибель/потеря корабля —
провал (счётчик провалов). Отказ: без пассажира — всегда; с пассажиром —
только стоя на планете (высадить). Цель заказа: жёлтый пульсирующий ореол
вокруг планеты в мире и на карте.

**Файлы.** `Orders/OrderService.cs`, `Physics/LandingSystem.cs`.

---

## 11. Пассажиры

**Идея.** Контент без программиста: персонажи — ScriptableObject'ы,
наполняются в инспекторе (задел на автогенерацию в бете).

**Реализация.** `PassengerProfile` (имя, архетип, описание, портрет +
оттенок — один спрайт даёт разных «людей», 4 пула фраз:
приветствие/пожелание/благодарность/жалоба). `PassengerCatalog` — список,
заказ берёт случайного. Фразы идут в карточки и тосты.

**Файлы.** `Orders/PassengerProfile.cs`, `Orders/PassengerCatalog.cs`,
ассеты в `ScriptableObjects/Passengers/`.

---

## 12. Станции

**Идея.** Ресурсное давление: заправка только на части планет — маршруты
надо планировать.

**Реализация.** Флаг `HasStation` в данных тела (чекбокс в редакторе
уровня). При посадке на планету со станцией — мгновенно полный бак и
полный корпус (событие `StationServiced` для тоста).

**Файлы.** `World/LevelAsset.cs`, `Physics/LandingSystem.cs`.

---

## 13. UI: layout-группы и редактируемый каркас

**Идея.** «Заставить UI слушаться»: элементы не могут налезать друг на
друга, новые вкладки добавляются без поломки.

**Реализация.** Панели строятся на автоматических раскладках:
`VerticalLayoutGroup` (стек секций) + `HorizontalLayoutGroup` (строки) +
`LayoutElement` (фикс/flex размеры). Ребёнок живёт только внутри родителя —
налезание невозможно по построению. Каркас бортового компьютера собирается
В РЕДАКТОРЕ (меню `Space Taxi → Rebuild Onboard Computer`) и
сериализуется в сцену — дальше правится руками, Play ничего не сносит;
runtime только привязывает данные к элементам по именам. Данные → UI
только через события (подписки на Ship/HullSystem/OrderService), никакого
опроса. Карточки заказов — рантайм-динамика с fade-анимацией появления.

**Файлы.** `UI/OnboardComputerFactory.cs`, `UI/OnboardBinder.cs`,
`Editor/OnboardComputerBuilder.cs`, `UI/HudBinder.cs`, `UI/ToastNotifier.cs`.

---

## 14. Камера и миникарта

**Идея.** Камера — следование с «дыханием» и посадочный зум; миникарта —
радар с честным масштабом.

**Реализация.** `CameraFollow`: позиция лерпом 3.5/с, орторазмер лерпом
3/с (320 в полёте, 190 на посадке). Радар: корабль всегда в центре,
позиция точки тела = `(мир − корабль) · масштаб`, охват 350 юнитов =
половина видимой области (правило «вижу на экране — вижу на радаре»),
размеры тел честные — при посадке круг планеты касается стрелки. Стрелка
вращается по вектору скорости.

**Файлы.** `Physics/CameraFollow.cs`, `UI/MinimapBinder.cs`,
`UI/MapScreenBinder.cs` (карта M строится из LevelAsset, не рисуется руками).

---

## 15. Звук

**Идея.** Архитектура звука с первого дня (решение проекта): события →
каталог → менеджер, замена клипа без кода.

**Реализация.** `AudioCatalog` (SO): 14 событий → клипы + громкость/pitch.
`AudioManager`: пул one-shot, лупы с фейдами, кроссфейд музыки 1.5 с,
ducking при взрыве, громкости групп в PlayerPrefs. Слайдеры настроек
меняют громкость вживую через публичный API менеджера.

**Файлы.** `Audio/AudioManager.cs`, `Audio/AudioCatalog.cs`,
`UI/SettingsBinder.cs`.

## 16. Архитектура в целом (ответ на «как организован проект»)

- **Данные отдельно от поведения**: ScriptableObject'ы (LevelAsset,
  PhysicsConfig, PassengerProfile, AudioCatalog) — контент и баланс без кода.
- **События вместо опроса**: игровые системы бросают события (HpChanged,
  ShipLanded, OffersChanged...), UI/звук подписываются — слабая связанность,
  новые потребители подключаются без правки систем.
- **Единые точки правды**: гравитация — только `GetAccelerationAt`;
  смена состояния заказа — только событие посадки; константы — только
  PhysicsConfig.
- **Editor/Runtime разделение**: инструменты (редактор уровня, билдер UI)
  в Assembly-CSharp-Editor, геймплой — в своей сборке `SpaceTaxi.Gameplay`
  (asmdef).
- **Мир строится из данных** при старте — сцены почти пустые.

## Частые вопросы преподавателя — короткие ответы

**Почему своя гравитация, а не Unity?** Встроенная — константный вектор;
нужна суперпозиция N тел по 1/d² с клампом — это свой расчёт в FixedUpdate,
Unity-физика отвечает только за коллизии.

**Почему ускорение пишется в скорость напрямую?** Управляем хотим точное
«пиксель-в-пиксель» соответствие HTML-прототипу (эталон ощущений) —
интегратор Эйлера, как в прототипе.

**Почему MAXV не жёсткий кламп?** Физически честно: тяга не работает выше
порога, но гравитация может разогнать и сильнее (как в реальности).

**Зачем ScriptableObject?** Данные уровня/баланса/пассажиров правятся в
инспекторе без пересборки; это и есть «уровень как данные».

**Как гарантируются правила игры кодом?** Один активный заказ — поле Active
и проверка в Accept; пассажир берётся/сдаётся только через событие посадки;
топливо тратится только при нажатой тяге; пустой бак — двигатели
заблокированы в контроллере.

**Почему события, а не Update-опрос?** UI перерисовывается только при
изменении; системы не знают о существовании UI (можно добавлять интерфейсы
не трогая ядро).

**Как тестировалось?** Автоматическая проверка компиляции через Unity CLI
на каждой итерации + сценарные ручные прогоны по чек-листам (прототип v0.1
закрыт, альфа — по чек-листу 12 §8).
