## 2. Физика [УТВЕРЖДЕНО — из ТП]

- Rigidbody2D, гравитация Unity выключена (Gravity Scale = 0)
- Свой закон обратных квадратов: `a = G·M / r²` от каждого тела, суммируется,
  применяется в FixedUpdate
- Управляем корабль через `rigidbody.AddForce` (THRUST/RETRO/STRAFE_ACC из `01_MECHANICS.md`)
- Скорость клампится к MAXV
- «Качель»: буст ×1.15 при разгоне в мощном гравитационном поле [детали уточнить при реализации]
- Контакт планеты: `OnCollisionEnter2D`, скорость касания решает посадка/урон
- Прогноз траектории: пошаговая симуляция тех же формул (N секунд вперёд),
  отрисовка пунктиром (LineRenderer) [УТВЕРЖДЕНО — из ТП]

### Согласование с прототипом

Единицы прототипа — пиксели/секунды canvas. В Unity 1 юнит = 1 «пиксель прототипа»
на старте [ПРЕДЛОЖЕНО]; масштаб камеры и спрайтов подгоняется под этого соответствия,
чтобы константы (95/115/330/38...) переехали без пересчёта. Если ощущения
расходятся — правим множитель масштаба мира, а не каждую константу.

## 9. Unity CLI — управление живым редактором [УТВЕРЖДЕНО — добавлено 2026-09-12]

Установлен Unity CLI **1.0.0-beta.9** (бинарник: `~/.unity/bin/unity`), в проекте есть
пакет `com.unity.pipeline` (0.7.0-exp.1). CLI управляет ОТКРЫТЫМ редактором
(порт 7800). Также в ZCode установлен плагин `unity-agent-plugin` (скиллы лучших
практик Unity, подхватываются в новых сессиях).

### Основные команды

| Задача | Команда |
|---|---|
| Проверить связь | `~/.unity/bin/unity status` (state=ready) |
| Список всех команд редактора | `unity command` |
| Выполнить C# в редакторе | `unity command eval '<statement>;'` |
| Создать/изменить объекты | `add_component`, `attach_script`, `batch` (транзакционно) |
| Play mode | `editor_play` / `stop` / `pause` |
| Скриншоты | `capture_game_view`, `capture_scene_view` |
| Сборка | `build` + `build_status` |
| Тесты | `list_tests`, `run_tests`, `cancel_tests` |
| Логи/консоль | `Logs/Editor.log` проекта, `clear_console` |

Всегда передавать `--project-path /Users/maxim/Desktop/SpaceTaxi/SpaceTaxiUnity/SpaceTaxi`.

### Приёмы и особенности (выяснены на практике)

- `eval` принимает **statement** (не expression): в конце `;`, результат-выражение
  нельзя — только присваивание/вызов (`Debug.Log(...)`, `var x = ...;`)
- Внутренний таймаут main thread — 5000 мс: если редактор занят (компиляция,
  импорт, модальное окно, зависший мастер создания проекта), команды падают
  с «Main thread operation timed out». Лечение: подождать / сфокусировать окно /
  перезапустить редактор через Hub (НЕ через -createproject)
- Safe Mode (ошибки компиляции C#) = pipeline не грузится, коннекта нет вообще;
  чинить ошибки по файлам, потом перезапуск
- `attach_script` может вернуть recoverable-ошибку, если тип ещё не скомпилирован:
  дождаться компиляции (`recompile_status`) и повторить
- После правок скриптов на диске редактор сам импортирует их; при ошибках —
  читать Editor.log

### Типовой цикл итерации

```
1. Правлю .cs на диске (редактор сам импортирует)
2. eval / recompile_status — убеждаюсь, что компиляция прошла без ошибок
3. apply: attach_script / add_component / eval-настройка сцены
4. Говорю пользователю «можно проверять» — ОН сам запускает Play Mode
5. Пользователь описывает результат словами; я читаю Editor.log на ошибки
```

**Правило [УТВЕРЖДЕНО]:** агент НЕ запускает Play Mode (`editor_play`) и не проверяет
геймплей скриншотами — только компиляция, ошибки, логи и применение изменений в сцену.
