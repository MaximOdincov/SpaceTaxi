# 08 — ПРОТОТИП v0.1: план и задания по ролям

Первая цель: простейший играбельный прототип для проверки ядра. Этот документ —
бриф для рабочих сессий по ролям (программист, UI-дизайнер, саунд-дизайнер,
левел-дизайнер). Общие правила работы — в `00_MAIN.md`.

---

## 1. Что такое «готово» для v0.1

Игрок из меню запускает новую игру, летает между планетами с ньютоновским
притяжением, садится, получает урон от столкновений и жара звёзд, видит HUD
(прочность, топливо), пользуется мини-картой, слышит звуки, читает начальный
монолог диспетчера на бортовом компьютере (TAB), открывает карту системы (M)
и паузу (ESC). Выход в меню сохраняет игру, «Продолжить» восстанавливает.
Уровень собирается визуальным редактором в Unity Editor.

**Что НЕ входит (не делать, даже если кажется простым):** система заказов,
пассажиры, прокачка/покупка кораблей, заправка/ремонт, экономика/долги,
красивая графика (только геометрические заглушки), финальный маршрут.

## 2. Скоуп по блокам [УТВЕРЖДЕНО]

### Меню
- «Продолжить» (кнопки БЕЗ сейва нет вообще, с сейвом — первая + под ней строка
  «сейв: дата · планета»), «Новая игра», «Настройки», «Выход» [обновлено 2026-09-16]
- Пока без красоты — фон с анимацией добавим позже

### Сохранение
- Автосейв при выходе в меню и при выходе из игры
- Сохраняется: позиция и скорость корабля, прочность, топливо, текущий уровень, настройки

### HUD
- Прочность (падает от столкновений и жара), топливо (в v0.1 НЕ расходуется — просто индикатор), скорость
- Счётчик доступных заказов — в v0.1 скрыт (заказов нет) [2026-09-16]
- Мини-карта: круглая, локальный фрагмент вокруг корабля (не весь мир), реальные
  уменьшенные планеты/звёзды с обводкой, игрок — стрелочка [обновлено 2026-09-16,
  было «объекты — квадратики»; детали — `10_UI_DESIGN.md` §4]

### Мир и физика
- Планеты: притяжение, посадка; звёзды: притяжение + жар (урон в жаровых зонах)
- Движение: W — тяга по курсу, S — тормоз, A/D — боковая тяга
- TAB — бортовой компьютер (панель слева, без паузы), M — карта системы (зум-аут,
  пауза, имена планет), ESC — пауза + меню паузы [2026-09-16]
- Свободный полёт по открытой карте между несколькими планетами
- Механики посадки пока не отполированы — черновые, на проверку
- HP = 0 → мгновенный респавн на стартовой планете с полным HP

### Бортовой компьютер
- Начальный монолог диспетчера (3–6 реплик, диалогов нет — один говорящий)
  [обновлено 2026-09-16]
- Секции заказов/экономики/плеера — по полной схеме `10_UI_DESIGN.md` §5,
  в v0.1 скрыты или заглушки (решить при сборке, вопрос №5 в `10_UI_DESIGN.md` §11)

### Карта (M) [добавлено 2026-09-16]
- Зум-аут всей системы (TestLevel01), пауза, имена планет, автоматически открытый
  бортовой компьютер слева
- Клик по телу → карточка тела: желательно, можно упростить до названия/массы/дистанции

### Звук
- Базовый набор звуков (список — бриф саунд-дизайнера, §5)

### Редактор уровня
- Инструмент в Unity Editor (кастомное окно, НЕ внутриигровой)
- Добавление/удаление космических тел, настройка размера и силы притяжения (и жара для звёзд)
- Всё видно визуально: радиусы, зоны — прямо в Scene View, легко и просто

## 3. Архитектура сущностей [ПРЕДЛОЖЕНО — база для программиста, уточнить при реализации]

### Игровые сущности (runtime)

| Сущность | Ответственность |
|---|---|
| `CelestialBody` | базовое космическое тело: позиция, радиус, масса (сила притяжения), видимость на мини-карте |
| `Planet : CelestialBody` | посадка: контакт по скорости → сесть или урон |
| `Star : CelestialBody` | + жар: радиус жаровой зоны, урон HP/с внутри зоны |
| `Ship` | корабль игрока: Rigidbody2D, thrust/retro/strafe, HP, топливо (в v0.1 не тратится), состояния Flying / Landed / Respawning |
| `GravityField` | суммарное ускорение от всех тел (закон обратных квадратов), единая точка расчёта |
| `ShipController` | ввод W/S/A/D → силы на Rigidbody2D |
| `LandingSystem` | определение посадки/столкновения (порог скорости), отскок, урон |
| `HullSystem` | HP, получение урона, смерть → респавн |
| `GameSession` | состояние текущей игры, ссылка на уровень, автосейв |
| `WorldBuilder` | строит сцену из данных уровня (`LevelAsset`) при старте |
| `HUD`, `MiniMap` | отображение состояния; мини-карта — локальный фрагмент, реальные мини-планеты с обводкой, стрелка игрока (`10_UI_DESIGN.md` §4) |
| `OnboardComputer` | панель слева (TAB/M/ESC), монолог с фото говорящего, секции: состояние/заказ/экономика/плеер (`10_UI_DESIGN.md` §5) |
| `MapMode` | карта системы M: зум-аут, пауза, имена планет, выбор тела → карточка (`10_UI_DESIGN.md` §6) |
| `PauseMenu` | пауза ESC: борт.комп слева + меню справа (`10_UI_DESIGN.md` §7) |
| `AudioManager` | события звуков, громкости групп (см. `05_AUDIO.md` §3) |
| `SaveSystem` | сериализация/загрузка сейва (JSON, persistentDataPath) |
| `MainMenu`, `SettingsMenu` | меню и настройки (прим: громкость) |

### Данные (не сцена!)

| Ассет | Что хранит |
|---|---|
| `LevelAsset` (ScriptableObject) | список тел: тип (Planet/Star), позиция, радиус, множитель массы, радиус жара (для звёзд); точка старта игрока; имя уровня |
| `PhysicsConfig` (ScriptableObject) | константы физики из прототипа (THRUST=95, RETRO=115, STRAFE_ACC=85, MAXV=330, LAND_SPEED=38, множители) — правки баланса без пересборки кода |
| Сейв (JSON) | levelName, позиция/скорость/HP/топливо корабля, настройки |

Принцип: сцена почти пустая, весь мир строится кодом из `LevelAsset`.
Редактор уровня (Editor-окно) пишет в `LevelAsset`, геймплей читает из него.

### Статус реализации (2026-09-12)

Готово (скелеты, `feature/v0.1-core-entities` слита в main): сборка `SpaceTaxi.Gameplay`
(asmdef), `PhysicsConfig`, `LevelAsset` (+`CelestialBodyData`, `BodyType`),
`CelestialBody`/`Planet`/`Star`, `Ship` (+`ShipState`), `ShipController`,
`GravityField`, `HullSystem`, `LandingSystem`, `GameSession`.

Звук (2026-09-13, задача 9): `SoundId`/`AudioGroup`, `AudioCatalog` (SO),
`AudioManager` (+фасад `Sound`), `ShipAudio`, `HeatAudio`, `SceneMusic`;
клипы CC0 в `Assets/Audio/`, каталог `Assets/ScriptableObjects/AudioCatalog.asset`,
обе сцены содержат AudioManager + SceneMusic. Детали — `05_AUDIO.md`.

Отложено: `WorldBuilder` — после обсуждения структуры уровня с левел-дизайнером;
`HUD`, `MiniMap`, `OnboardComputer`, `SaveSystem`, `MainMenu`,
`SettingsMenu` — свои итерации по брифу §4.

Эталонные формулы из HTML-прототипа (сверка 2026-09-12, для итерации физики):
гравитация `a = min(g/d², 240)`, `g = 26000·r·mult` (планета 1, звезда 4.5);
тяга/тормоз/стрейф применяются к вектору скорости, при v ≥ MAXV тяга не работает
(это не жёсткий кламп); качель ×1.15 на входе в ring при v > vEsc; жар до 30 HP/с
у поверхности (heat = r·3.6); камера — лерп позиции 3.5/с, зума 3/с.
Автопилот циркуляции из прототипа в игру НЕ переносим (решение 2026-09-13) —
рядом с планетами только ньютоновская физика.

## 4. БРИФ: ПРОГРАММИСТ

**Цель:** все системы из §2–3 работающими, без ошибок компиляции.

Читай: `00_MAIN.md`, `01_MECHANICS.md` (§1–3), `06_TECH_ARCHITECTURE.md` (всё, особенно §9 — Unity CLI: проверяй компиляцию сам, Play Mode запускает пользователь).

**Порядок задач (каждая — отдельная итерация с проверкой):**

1. **Каркас проекта**: папки, сцены (Menu, Game), `PhysicsConfig`, пустой `LevelAsset`, WorldBuilder строит 3 тестовые планеты из данных. Заглушки спрайтов кодом (круги/треугольник)

3. **Планеты и посадка**: контакт по порогу скорости (посадка/урон+отскок), состояния корабля, взлёт с планеты
4. **Звёзды**: жар, урон HP/с, визуальная индикация зоны (заглушка)
5. **HP и респавн**: урон от столкновений и жара, HP=0 → респавн на старте

7. **Меню + сейв**: MainMenu (кнопки: Продолжить [нет без сейва] / Новая игра /

8. **Бортовой компьютер + карта + пауза**: панель слева (TAB, анимация выезда,
   без паузы — `10_UI_DESIGN.md` §5), монолог диспетчера (текст-заглушка),
   карта M (зум-аут, пауза, имена планет, панель открывается), пауза ESC
   (меню: продолжить/настройки/выход)
9. **Звук**: AudioManager + события по `05_AUDIO.md`, подключение клипов когда саунд-дизайнер их даст
10. **Редактор уровня**: EditorWindow — список тел уровня, добавить/удалить (планета/звезда), редактирование параметров, гизмо в Scene View (радиус тела, кольцо зоны посадки, жаровая зона), сохранение в `LevelAsset`. Drag тел прямо во Scene View — если успеется без боли, иначе стрелки/поля

**Готовность:** чек-лист §7 полностью зелёный, ошибок компиляции нет, ручной прогон пользователя без крашей.

## 8. Порядок работы и зависимости

```
Программист: каркас ──► физика ──► планеты/посадка ──► звёзды/HP ──► HUD/миникарта ──► меню/сейв ──► борт.комп ──► звук ──► редактор уровня
UI-дизайнер:      меню+HUD макеты (параллельно, нужно к задачам 6-8 программиста)
Саунд-дизайнер:   подбор звуков (параллельно, нужно к задаче 9)
Левел-дизайнер:   ТЗ редактора (параллельно) ────────────────────► сборка уровня (после задачи 10)
```

- Программист стартует первым — физика (задачи 1–5) не зависит ни от кого
- UI-макеты успевают к интеграции HUD/меню; до тех пор программист ставит серые заглушки
- Звуки успевают к задаче 9; до тех пор события зовутся с пустыми клипами
- Редактор уровня — последняя задача программиста, после неё левел-дизайнер собирает карту
- Всё через игровые сессии с ролями: каждая сессия читает этот док + свой бриф
