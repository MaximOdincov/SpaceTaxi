# STUDY PLAN — как выучить кодовую базу SpaceTaxi за 3 вечера + 1 повторение

Инструменты: ты на ветке `feature/beta-annotated` (построчные комментарии справа — ядро:
Core/Physics/World); рядом держи открытые `docs/ARCHITECTURE.md` (карта) и
`docs/CODE_REVIEW_N9.md` (что хвалить/защищать). Отладчик важнее чтения: физику и
сценарии прогоняй брейкпоинтами. Orders/Economy/Audio/UI пока БЕЗ построчных
комментариев (в план вечера 3 заложено чтение по методам — добавим комментарии следом).

---

## Вечер 1 (~2.5–3 ч) — Скелет: сборка игры и полёт

Цель вечера: рассказать путь «двойной клик по сцене → первый кадр полёта» не подглядывая.

Читать в этом порядке (суммарно ~1600 строк):
1. `docs/ARCHITECTURE.md` §1–2 (15 мин) — карта в голове до кода.
2. `Core/GameSession.cs` — композиционный корень: что создаётся в Awake, что в Start,
   кто чей подписчик (это скелет всего остального).
3. `World/LevelAsset.cs` — уровень как данные (тела/пояса/сектора/старт).
4. `World/WorldBuilder.cs` — фабрика мира: тела → пояса → кометы → корабль.
5. `World/CelestialBody.cs` (+ `Star.cs`/`Planet.cs` по 20 строк) — Init, кольца, реестр.
6. `Physics/GravityField.cs` — 40 строк: реестр + суперпозиция 1/d².
7. `Physics/Ship.cs` + `Physics/ShipStats.cs` + `Physics/PhysicsConfig.cs` — статы,
   Eff как единственный источник чисел.
8. `Physics/ShipController.cs` — ГЛАВНОЕ чтение вечера: FixedUpdate (Эйлер, тяга,
   тормоз с «полом», качели у кольца, топливо), UpdateHeading, Update (заморозка/взлёт).

Практика: брейкпоинт в `ShipController.FixedUpdate`; в инспекторе посмотреть `Eff`
на живом корабле; покрутить `PhysicsConfig_Default` (тяга/гравитация) и почувствовать.

Проверь себя (ответить вслух):
1. Почему у Rigidbody `gravityScale = 0`?
2. Что делает `BrakeHoverFraction` и почему без него корабль «висел в воздухе»?
3. Когда срабатывают качели и почему у планет буст отключён?
4. Почему MaxV не клампит скорость наглухо?
5. Полный путь нажатия SPACE до движения корабля (Update → Takeoff/тяга → FixedUpdate).

## Вечер 2 (~3 ч) — Опасности и жизнь корабля

Цель вечера: объяснить любой инцидент «что случилось с кораблём и почему» по коду.

1. `Physics/LandingSystem.cs` — контакты, кэш `preSolveVelocity` (почему он нужен),
   `CrashDamage` (квадрат скорости), предиктивная посадка, дожим, `Takeoff`.
2. `Physics/HullSystem.cs` — урон/жар/`Die`/`Abandon`, `RespawnAfter` (включая
   Н9.14: корпус прячется мгновенно и появляется по прилёту камеры).
3. `World/BlackHole.cs` — самый насыщенный файл: воронка (depth²), захват (гистерезис),
   окно 45с ease-out, «застрявший» (силовое сравнение тяги), обломок. + `World/WreckSystem.cs`
   (два режима: спираль и орбита-угасание).
4. `World/AsteroidBeltSystem.cs` + `World/CometSystem.cs` — зоны, отсев планет, хорды.
5. `World/StarfieldParallax.cs` — быстро, по диагонали.

Практика: плейтест дыры по шагам (X-флоу из Н9.12) с логами `[BlackHole]`; плейтест
посадки/удара с логами `[Landing]`.

Проверь себя:
1. Зачем `preSolveVelocity` и что ломается без него?
2. Чем `Die` отличается от `Abandon` (визуал, события, респавн)?
3. Как дыра решает «исход силой» — что такое «застрявший» и орбитальный потолок?
4. Что игрок видит пошагово после нажатия X (обломок → тост → камера → появление)?
5. Почему обломок кинематический, а не физический?

## Вечер 3 (~3 ч) — Деньги, задания и подача

Цель вечера: провести один заказ «руками кода» от спавна карточки до сейва.

1. `Economy/OrderPricing.cs` (формула цены, 27 строк) → `Economy/PricingConfig.cs`
   (структура ассета) → `Wallet.cs` → `DebtService.cs` → `PayoutService.cs` (порядок
   штраф→комиссия→чаевые→долг) → `FleetService.cs` (парк/апгрейды) →
   `FuelNetwork.cs` (детерминизм «сухих» станций) → `RatingService.cs`.
2. `Orders/OrderService.cs` (автомат Offered→Active→Aboard→…, спавн карточек, трекинг
   заданий) + `Orders/PassengerTask.cs` (9 видов, тексты в одном месте).
3. `Audio/AudioManager.cs` (группы, пул голосов, музыка/станции, сторож тишины) +
   фасад `Sound` + `SceneMusic.cs`/`ShipAudio.cs` (образцовые отписки).
4. `Physics/EngineEffects.cs` + `Physics/ShipExplosion.cs` — процедурные частицы.
5. UI (читать по методам, не подряд): `OnboardComputerFactory` → `OnboardBinder` →
   `HudBinder` → `ToastNotifier` (пул+очередь) → `MinimapBinder` → `WaypointIndicator`
   → `MapScreenBinder` (структура: BuildMap/Update/LateUpdate/легенда/зум) →
   `StationScreenController` (структура) → `Core/SaveSystem.cs`.

Практика: принять заказ и донести, следя за событиями (брейкпоинты на
`OrderAccepted/PassengerBoarded/OrderDelivered/Payout.Pay`).

Проверь себя:
1. Порядок выплаты и почему Wallet — единственная точка списания?
2. Когда фиксируется цена заказа и зачем?
3. Три примера «события вместо опроса» из кода.
4. Что рисуется в одном кадре карты и кто этим управляет?
5. Что входит в сейв, а что сознательно не входит (настройки/реплики/позиции зон)?

## Правила чтения

- Читая файл, сначала пробеги его комментарии-историю (они объясняют «почему так»),
  потом код.
- Незнакомый термин → `docs/ARCHITECTURE.md` → код → отладчик.
- Не читай 3000-строчные файлы подряд: `MapScreenBinder`/`StationScreenController`
  — по методам, от точки входа (Update/BuildXxx) по вызовам.
- Любой сценарий проверяется запуском, а не только чтением: брейкпоинт + плейтест.
