## Задача 1 — шапка состояния борткомпа ✅ DONE

**Симптом владельца воспроизведён и починен.** Корень найден НЕ из списка кандидатов брифа
(шрифт был жив, JetBrains на месте, якоря работали):

- **Истинная причина: TMP `overflowMode=Ellipsis` обрезает текст и ПО ВЕРТИКАЛИ.**
  Фабрика строит тексты с `overflowMode=Ellipsis`; когда фиксированная высота узла меньше
  высоты строки шрифта, TMP не помещает НИ ОДНОЙ строки → `textInfo.characterCount=0`,
  пустой меш → текст «есть, но невидим». Проверено вживую: `preferredHeight=47.52` при
  `rect=44`; переключение режима на `Overflow` в плее мгновенно давало 5 видимых символов.
- Высоты строк JetBrainsMono: 36pt ≈ 47.5px (шапка в 44px — битая), 21pt ≈ 27.7px
  (заголовки секций в 26px — битые), 23pt ≈ 30.4px (имя пассажира в 28px — битое).
  Поэтому владелец не видел и заголовки `// …`, и имена в карточках — тот же корень.
- Регрессия пришла из прошлой сессии: переход шапки на ручные якоря зафиксировал высоты
  текстов (44), а раньше HorizontalLayoutGroup сам давал тексту preferred-высоту.

**Файлы:** `Assets/Scripts/UI/OnboardComputerFactory.cs`
- `AnchorHeaderEdge`/`AnchorHeaderCenter`: высота текстов шапки 44 → **48**;
- заголовки секций: 26 → **28**; имя в компактной карточке: 28 → **31**;
- в оба `AnchorHeader*` добавлен get-or-add `LayoutElement` c `ignoreLayout=true`
  (было: LE отсутствовал на текстах фабрики → ignoreLayout молча не ставился,
  HorizontalLayoutGroup с `childControlWidth=true` перебивал ручные якоря);
- в `Text()` добавлено предупреждение о вертикальной обрезке Ellipsis.
- `Assets/Scripts/UI/OnboardComputerPanel.cs`: `Application.runInBackground = true` в `Awake()`.
