## ПРАВИЛА РАБОТЫ
1. Последовательно, ОДИН чекаут: `/Users/maxim/Desktop/SpaceTaxi/SpaceTaxiUnity/SpaceTaxi`
   (git). База — `feature/beta`. Без worktrees.
2. Цикл задачи:
   a. `git checkout -b agent/n2-<slug>` от feature/beta.
   b. Субагент-исполнитель: дать путь к брифу (§4) + путь API-карты
      `/Users/maxim/Desktop/SpaceTaxi/NIGHT_API_MAP.md` (вкл. «ДОПОЛНЕНИЕ НОЧИ»)
      + §2 контекст-блок из 21-го файла. Отчёт исполнителя ≤ 15 строк.
      Субагент НЕ мержит, НЕ трогает GameInfo, НЕ запускает Unity.
   c. Компиляция (см. ниже). Ошибки → вернуть исполнителю по SendMessage
      (у него контекст) → фикс-коммит → перекомпиляция. Максимум 3 попытки.
   d. После порции (2–3 задачи) — ревью субагентом (read-only, дифф порции),
      P0/P1 чинить сразу (можно самому, это точечные правки), P2 — в лог.
   e. `git checkout feature/beta && git merge --no-ff agent/n2-<slug>`,
      удалить ветку, обновить лог (хэш merge), след. задача.
3. Компиляция — ЕДИНСТВЕННО правильный вызов (`~/.unity/bin/unity` — это НЕ
   редактор, не использовать!):
   ```
   "/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity" -projectPath "/Users/maxim/Desktop/SpaceTaxi/SpaceTaxiUnity/SpaceTaxi" -batchmode -quit -nographics -logFile "/Users/maxim/Desktop/SpaceTaxi/night_compile2.log"; echo "UNITY_EXIT: $?"
   ```
   UNITY_EXIT 0 = успех; иначе `grep "error CS" night_compile2.log`.
   Второй экземпляр Unity параллельно НЕЛЬЗЯ (lock). Пока компиляция идёт —
   не переключать ветку и не править файлы репо. Если существует
   `SpaceTaxi/Temp/UnityLockfile` — редактор открыт: компиляция невозможна,
   ждать/логировать, код писать можно.
4. Запреты: не пушить; не мержить в main; Play Mode и Unity Editor не
   запускать; сцены/префабы YAML руками не править; баланс-числа не менять
   (если явно даны в брифе — можно); GameInfo/17 и GameInfo/19 не трогать.
   Правки GameInfo допускаются ТОЛЬКО если бриф их прямо разрешает (21 §4
   помечает такие места).
5. Новые .cs без .meta: если исполнитель сам не создал — создай сам
   (fileFormatVersion 2 + свежий GUID) или закоммить сгенерённый компиляцией
   до merge (смотри git status после компиляции).
6. Неоднозначности: решать по брифам и докам (16_BETA_PLAN, 21), решение —
   в лог («РЕШЕНИЯ»). Вопросы владельцу копить в лог («ВОПРОСЫ УТРА») —
   владелец ответит утром.
7. Блокер задачи (компиляция не чинится за 3 попытки, репо сломан):
   в лог «БЛОКИ», откат (`git checkout feature/beta && git branch -D ...`),
   переходить к следующей задаче реестра. Ночь НЕ останавливать.
   Блоки — первые кандидаты на утро.
8. Арт-текстуры НЕ генерировать и НЕ ждать их: владелец генерит по 21 §7.

   Звук-файлы может положить владелец — если файла нет, пометить «ждёт файл»
   и идти дальше (см. Н-6).
9. По завершении реестра: обновить статусы в 21-м файле (§1 колонка Статус),
