2. **Лимит параллельности — 2 агента** (в Н7 третий запуск отклонялся `user concurrency limit

3. Дисциплина редактора: редактор гоняют ТОЛЬКО назначенные редактор-агенты (по одному за
   волну), офлайн-агенты НЕ запускают никаких unity-команд; субагент после КАЖДОЙ плей-проверки
   — editor_stop и убедись playMode=stopped; занятый редактор → пауза 60-90с, макс 3 попытки →
   офлайн; оркестратор перед редактор-агентом: editor_status (ready, stopped) + recompile.
4. Скорость: застрял >20 мин — PARTIAL, коммит, следующая задача. Честный PARTIAL лучше «на глаз».
5. Сцены руками (YAML) не править — только eval/SerializedObject. Внешне изменённый .unity →
   перезагрузить сцену. Сейв не трогать. git-историю не переписывать. НЕ пушить.
6. Лог `docs/NIGHT_LOG8.md`: по каждой задаче — статус/файлы/решения/проверка/вопросы/хэш.
   В конце: сводка, коммиты, чек-лист владельцу, уроки.
7. **Перед финалом — прогон по ВСЕМ нумерованным задачам этого брифа** (в Н7 задача U7.3 молча

## СЛОЖНЫЕ СИТУАЦИИ И ИХ РЕШЕНИЯ (выучить до старта — всё проверено на Н6/Н7)

1. **Параллельность = 2 агента.** Третий Agent-запуск отклоняется мгновенно (`user concurrency
   limit exceeded`) без потери контекста у первых двух. Строй волны по 2; отклонённый перезапусти,
   когда освободится слот.
2. **Pipeline eval main-thread окно ~5с.** Долгие операции (ForceSynchronousImport, OpenScene,
   SaveAssets, импорт аудио) возвращают `COMMAND_FAILED: timed out after 5000ms`, НО операция
   обычно успевает выполниться — после таймаута ПРОВЕРЬ фактическое состояние (файлы/.meta/
   SerializedObject/активная сцена), не повторяй вызов вслепую (риск двойного применения).
3. **Eval-колбэки не переживают вызов CLI** — детерминированные замеры В ОДНОМ eval-вызове
   (ручные Physics2D.Simulate-шаги + Invoke приватных FixedUpdate через рефлексию), либо
   slow-mo с поллингом.
4. **Error Pause ловит ВСЁ** (включая шум pipeline-раннера): в каждом полле
   `if (EditorApplication.isPaused) EditorApplication.isPaused = false;`.
5. **capture_game_view врёт при несфокусированном редакторе** — только
   `UnityEngine.ScreenCapture.CaptureScreenshot("Temp/…png")` из eval; иногда не пишется с
   первого раза — повторить через кадр-другой. Счёт частиц/эффектов — В ТОМ ЖЕ eval, где спавнишь
   (unscaled time не замедляется timeScale).
6. **Domain reload в плее стирает delegate-списки** — подписки на события (HullSystem.Died и
   пр.) делать идемпотентным `-=+=` на каждый OnEnable/Update (Н7 M7.4: подписка молча умирала).
7. **CS0136 честное правило**: итерационная переменная foreach конфликтует с ЛЮБОЙ локалью с
   тем же именем в том же методе (даже объявленной НИЖЕ по коду). Офлайн-проверка dotnet-ом на
   вырезке без той локали даёт ложный вывод «квирк Unity». Сверяй весь метод.
8. **TMP_Text.alpha = альфа цвета** (отдельного множителя нет): BaseColor захватывать ДО
   гашения, фейд писать в color.
9. **uGUI 9-slice border делится на sprite.PPU / canvas.referencePixelsPerUnit** — канвас
   MainMenu с ReferencePPU=1000 раздувает рамку ×10; спрайт-генератор принимает ReferencePPU
   канваса (MenuGlowSprite.Rim).
10. **Сцены (.unity YAML) руками не править** — SerializedObject/eval; внешний .unity →
    перезагрузить сцену; LevelAsset-правки (M8.4) — только SerializedObject в редакторе.
11. **TMP-ассет через AddObjectToAsset** (atlasTexture+material), иначе m_AtlasTextures ломается
    после domain reload.
12. **Сверяй раздачу задач с разделом ЗАДАЧИ брифа** перед финалом (Н7: U7.3 выпала из волнового
    плана, поймана только сверкой).
13. **Редактор занят → не ждать**: пауза 60-90с, макс 3 попытки → офлайн-работа + пометка.
    Оркестратор перед редактор-агентом: editor_status + recompile. Плей останавливает ТОЛЬКО
    тот, кто запустил.
14. **ВКУС ВЛАДЕЛЬЦА**: чистые спрайты без фильтров/теней/тонировок; жёлтый = цель, зелёный =
    метка игрока; любое украшательство — только по прямому запросу брифа. Н7-урок: отмывка,
    тени, янтарный акцент, мышиный параллакс — отвергнуты.
