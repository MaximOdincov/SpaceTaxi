## ЗАДАЧА

1. **Рейтинг таксиста** — `Assets/Scripts/Economy/RatingService.cs`, plain C#
   (владелец GameSession, свойство только для чтения `Rating`):
   - `float Value` (0.0–5.0, старт новой игры 3.0), `event Action<float> RatingChanged`,
     шаг 0.1, кламп [0.0; 5.0].
   - API (каждый метод двигает Value и шлёт событие):
     `void AddDelivery()` (+0.15), `void AddCollisionPenalty()` (−0.10),
     `void TaskCompleted()` (+0.10 — вызовов пока нет, хук для П5.3/П8.2),
     `void FailNoDeath()` (−0.30), `void FailWithLoss()` (−0.50).
   - Связка в GameSession: OrderDelivered → AddDelivery; OrderCancelled →
     FailNoDeath; OrderFailed → FailWithLoss; LandingSystem.CrashImpact при
     наличии Active (orders.Active != null) → AddCollisionPenalty (и штраф
     выплаты в П4.2 считает OrderService — не задвоить: рейтинг слушает
     CrashImpact напрямую, выплата — счётчик OrderService; это два независимых
     потребителя одного события).
2. **Эффекты рейтинга** (числа в PricingConfig, ассет дополнить):
   - `RatingPriceBonusThreshold = 4.0`, `RatingPriceBonusMul = 1.1`:
     рейтинг ≥ 4.0 → +10% к цене предложения. Применение в OrderService.AddOffer:
     базовая цена × множитель (округление AwayFromZero). RatingService
     передаётся OrderService Bind-методом (без FindAnyObjectByType).
   - `LowRatingSpawnThreshold = 2.0`, `LowRatingSpawnSlowdown = 1.3`:
     рейтинг < 2.0 → задержки спавна карточек × 1.3 (используй существующие
     spawnMin/spawnMax как базу; не менять сами поля).
3. **Слот рейтинга в борткомпе**: узел `Stack/Header/StatsRow/RatingValue/Value`
   уже существует (OnboardRefs.RatingValue) — выводить «3.2» (одна десятая,
   всегда, даже 0.0), обновление по RatingChanged + первичный показ при бинде.
   Иконка ratingIcon уже в OnboardBinder — не трогать.
4. **Экран завершения заказа**:
   - `Assets/Scripts/UI/OrderCompleteScreenController.cs` (+ биндер по стилю
     соседей): модальный экран после доставки. Данные — результат последней
     выплаты: PayoutService хранит `PayoutResult LastResult { get; }`
     (П4.2 заполняет при Pay; если LastResult null — экран не открывать).
   - Содержимое: заголовок «ЗАКАЗ ВЫПОЛНЕН» (или имя пассажира + «доставлен»),
     строки разбивки: «Цена N кр», «Штраф −M кр (K столкн.)» (скрыть при 0),
     «Комиссия аренды −C кр» (скрыть при 0), «Чаевые +T кр» (скрыть при 0 —
     чаевые появятся в П8.2), «В счёт долга −D кр» (скрыть при 0),
     «ИТОГО +N кр» (акцент), «Рейтинг +0.15» (дельта последнего изменения —
     возьми из события/сервиса, формат «+0.15»).
   - Открытие: GameSession после выплаты (после вызовов тостов) →
     `orderComplete.Show()`. Пауза мира: `Time.timeScale = 0` на время экрана,
     восстановление при закрытии (гарантированно: закрытие любым из путей
     возвращает 1).
   - Закрытие: кнопка «ПРОДОЛЖИТЬ», клавиши Esc/Space/Enter. Конфликт ESC с
     паузой решай как MapScreenController (смотри фактический договорённости
     NotifyMapOpened/Closed — добавь симметричные NotifyOrderCompleteOpened/
     Closed в PauseScreenController; при открытом экране завершения ESC
     закрывает ЕГО, пауза не открывается).
   - Экран строится кодом при первом показе (паттерн StationScreen П3.1),
     фабричные цвета/шрифт как у соседей, НИКАКИХ правок .unity/.prefab руками.
