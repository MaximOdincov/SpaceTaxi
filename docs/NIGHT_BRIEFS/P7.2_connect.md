## ЗАДАЧА

1. **Подключение карты**: GameSession в сцене GameScene.unity ссылается на
   AlphaMap01 полем `level` (GUID-ссылка в YAML). Заменить ссылку на
   BetaMap01.asset:
   - Узнай guid BetaMap01 из его .meta; найди строку `level: {fileID: 11400000,
     guid: <alpha-guid>, type: 2}` в Assets/Scenes/GameScene.unity — замени
     ТОЛЬКО guid на beta-guid. Проверь `grep -c` ДО/ПОСЛЕ: у AlphaMap01-гуида
     была ровно 1 ссылка в сцене, после правки — 0 (и 1 beta).
   - БОЛЬШЕ В СЦЕНЕ НИЧЕГО НЕ ТРОГАТЬ. Дифф должен быть однострочным.
2. **Астероиды поверх планет** (подозрение П7.1): осевые планеты пар лежат на
   оси поясов — астероид может заспавниться внутри планеты. В AsteroidBeltSystem
   добавь отсев: WorldBuilder передаёт системе список позиций+радиусов планет
   (Type == Planet из level.Bodies); при размещении астероида — rejection
   sampling (до N попыток, потом сдвиг угла) с запретом дистанции до центра
   планеты < planetRadius + asteroidRadius + 8.
3. **Южный квадрант комет** (§4: кометы 2–3 маршрута, Y < −900):
   - В LevelAsset добавить поля `Vector2 CometAreaCenter = zero`,
     `float CometAreaRadius = 0` (0 = случайные хорды по всему миру — старое
     поведение CometSystem П6.3).
   - CometSystem: если CometAreaRadius > 0 — хорды выбирать ВНУТРИ этой
     окружности (точки входа/направления случайные, маршруты не покидают
     окружность; безопасный минимум от спавна планеты старта сохранить —
     см. фактический код П6.3 про ≥500 от SpawnPoint).
   - BetaMap01.asset: CometAreaCenter = (0, −1300), CometAreaRadius = 700
     (южный квадрант; если в BetaMap01 южный квадрант занят телами плотно —
     подвинь центр/радиус так, чтобы кометы не рождались внутри тел, и
     отчитайся).
3. **Хаб-визуал до арта**: планета «Гавань» в BetaMap01 — UseColor = true,
   тёплый жёлтый (такси-цвет, константа (1, 0.83, 0.3) как TargetGlow) —
   чтобы хаб читался до арта А4. Остальные тела не трогать.
4. **Сверка цен по секторам** (приёмка §4, РАСЧЁТ, не правки):
   - По фактическим данным BetaMap01 посчитать вилку цен заказов:
     для каждой планеты-НАЗНАЧЕНИЯ по секторам — min/max цены по всем
     возможным pickup-планетам: цена = (40 + min(dist,1500)×0.25) × mul
     (mul сектора назначения: 1.0/1.0/1.3/1.6/2.0).
   - Сравнить с вилкой §4: «ближние 80–150 … дальние до 700».
   - В ОТЧЁТ: таблица (сектор → min–max фактически, вилка §4, ок/нарушено).
   - ЧИСЛА НЕ МЕНЯТЬ. Если вилка нарушена СИЛЬНО (в 2+ раза) — СТОП и
     сообщи координатору (решение по правке PricingConfig принимает
     координатор, не ты). Небольшие отклонения — просто в отчёт.
