## ЗАДАЧА

Точки интереса — задания архетипов Турист и Чудик (П5.3 оставила им None).
Механика трекинга — как у условий П5.3 (период Aboard→доставка, успех/провал,
рейтинг ±0.10 — фактический код).

1. Расширить `PassengerTaskKind` (PassengerTask.cs, П5.3): `CometFlyby,
   RingVisit, StarBackside, HoleFlyby, WaitOnPlanet` + поля для параметров:
   `float DistanceThreshold` (400/800), `int TargetBodyIndex` (планета/звезда —
   индекс в level.Bodies), `float WaitSeconds` (10), `float WaitAccumulated`
   (внутреннее).
2. Каталог (метод Create, П5.3): для Турист — случайный из:
   - CometFlyby: «Покажите комету! Пролетите в {0} юн от неё.» (400)
   - RingVisit: «Облетим кольцо планеты {0}?» (случайная планета НЕ pickup/dropoff;
     текст с именем планеты)
   - StarBackside: «С теневой стороны звезды {0} — говорят, вид необыкновенный.»
     (случайная звезда)
   Для Чудик — случайный из:
   - HoleFlyby: «Мимо бездны! Пролетите в {0} юн от чёрной дыры — и живыми.» (800)
   - WaitOnPlanet: «Посидим перед стартом на {0} минут десять. Тишина — тоже
     путешествие.» (случайная планета НЕ pickup/dropoff)
   ФОЛБЭК: если требуемого объекта в уровне нет (дыры нет в AlphaMap01;
   звёзд может не быть — смотри фактический уровень) — задача не выдаётся
   (None) или заменяется на доступный тип из того же архетипа (предпочтение —
   замена, чтобы Турист не оставался без задания; если совсем нечего — None).
   Комета ВИРТУАЛЬНО всегда есть (CometSystem), проверку существования делай
   по системе (если CometSystem в мире есть — задание доступно).
3. Трекинг (OrderService, период Aboard→доставка, СМОТРИ фактический П5.3-код —
   добавь в ТУ ЖЕ систему отслеживания, не новую):
   - CometFlyby: минимальная дистанция корабля до любой живой кометы за период
     < 400 → Succeeded (считай в Update по списку CometSystem.ActiveComets —
     смотри фактический API П6.3; если списка нет — добавь свойство).
   - RingVisit: корабль внутри CaptureRing целевой планеты → Succeeded.
   - StarBackside: корабль за звездой ОТНОСИТЕЛЬНО ЦЕНТРА МИРА: проекция
     (shipPos − starPos) на (starPos − worldCenter) > star.Radius → Succeeded.
   - HoleFlyby: минимальная дистанция до чёрной дыры (любой BlackHole в мире —
     смотри, как найти: GravityField.Bodies фильтр по типу) < 800 → Succeeded
     (гибель до успеха — заказ провалится сам, задача не успевает).
   - WaitOnPlanet: суммарное время State == Landed на целевой планете ≥ 10 с
     (копится с прерываниями, WaitForLanded-логика в Update).
4. Итог/отчёт: как у условий П5.3 (успех → RatingService.TaskCompleted +
   тост Thanks пассажира; провал → TaskFailed + жалоба) — если П5.3 сделала
   общий путь для всех Kind != None, тут может быть НОЛЬ нового кода в итогах.
   Чаевые НЕ начислять (П8.2).
5. UI: текст задания уже показывается (П5.3 — task.Text). НИЧЕГО нового в UI
   не требуется (прогресс «осталось секунд» — только у дедлайна; для WaitOnPlanet
   опционально добавь «посидели X/10 с» в статус активного заказа — если дёшево).
