## КАК РАБОТАТЬ С КОДОМ/РЕПОЗИТОРИЕМ/UNITY — РАБОЧИЕ ПРАВИЛА ДНЯ 15.11

**Unity/редактор:**
1. Редактор гоняет через unity-cli, port 7801 (`unity status`). Плей-режим: стартует/гасит
   АГЕНТ (`editor_play`/`editor_stop`), после каждой проверки — stop + убедись
   `playMode=stopped`. Ошибка паузы: `if (EditorApplication.isPaused) EditorApplication.
   isPaused = false;` в каждом полле.
2. **СТАРАЯ СЕССИЯ = СТАРЫЙ КОД.** После `unity recompile` ОБЯЗАТЕЛЬНО
   `editor_stop` → `editor_play` заново: живой плей-режим держит сборку до рестарта,
   «фиксы не работают» в половине случаев — это оно. Проверка фиксa — живой замер
   (eval-ом), не скриншотом из старой сессии (дважды сегодня ловили).
3. **Деградация сессии**: после 3-5 рекомпайлов/рестартов рендер умирает (чёрные кадры
   CaptureScreenshot, UI не рисуется, `fixedTime` стоит при живом `frameCount`) — лечится
   ТОЛЬКО рестартом плей-сессии (pause-toggle не всегда помогает). Чёрный кадр скриншота =
   замерить числом через eval (иерархии/позиции/альфы), скриншот повторить на новой сессии.
4. Сцены/.unity/.prefab руками не править — SerializedObject/eval. Ассеты .asset —
   то же (BetaMap01 hole R — через SerializedObject по индексу тела; PhysicsConfig —
   прямые поля). Внешне изменённый файл → перезагрузить сцену/ассет.
5. **Дефолты рантайм-компонентов** (OrderService и др., добавляемые AddComponent) —
   это ДЕФОЛТЫ КЛАССА, не сцена: правятся в .cs, SerializedObject по ним бесполезен
   в edit-режиме (компонента нет).
6. Лимит параллельных субагентов = 2; оркестратор принимает дифф/коммитит.

**Eval/CLI:**
7. Длинные eval-ы (>5с) молча теряются — «no output» ≠ «не выполнилось»: ПОСЛЕ каждого
   мутационного eval — контрольный eval состояния. Ошибся — не повторяй вслепую.
8. eval-ы с 10+ строками периодически тихо не выполняются — разбивай на шаги по 1-3
   утверждения, состояние проверяй отдельным вызовом.
9. Скриншоты: `UnityEngine.ScreenCapture.CaptureScreenshot("Temp/…png")` из eval
   (пайплайн-скриншот врёт без фокуса; чёрный кадр = деградация, см. п.3).
10. Локальные функции в eval-строке (`System.Func<...> f = ...`) ломают парсер —
    пиши без них (foreach + флаги).

**Код/рефакторинг:**
11. Точечные правки C# — патч-скрипты `Temp/patch_*.py` (Write tool → python Temp/…),
    НЕ heredoc в bash: heredoc с UTF-8/кавычками ломается молча и оставляет битые файлы
    (дважды за день). Скрипт = replace с assert «найдено», в конце print-статусы.
    Сломанный/упавший патч-скрипт = ПЕРЕЗАПИСАТЬ файл скрипта целиком (Write), не
    чинить её-документом.
12. Патч-скрипт умер на середине → файл-цель в промежуточном состоянии: перед повтором
    проверь, какие блоки уже применились, делай патч идемпотентным (`if old in s`).
13. **StubSprites запекает диаметр в PPU**: Ring/SoftDot/Circle(diameter) — спрайт
    `diameter` юнитов при scale=1. Итоговый размер = texturePPU-база × localScale.
    «Кольцо 58 000 юнитов за экраном» — это оно. Формула: localScale = целевой_диаметр/256.
14. Тексты игровых систем — в одном месте (для владельца): задания —
    `PassengerTasks.CreateRandom/SuccessMomentText/FailMomentText`; правки текстов =
    правки одного файла.
15. Новое задание пассажира = 3 шага: значение в `PassengerTaskKind` (условия ДО точек
    интереса — `IsInterestPoint = kind >= RingVisit`), кейс текста в `CreateRandom`,
    кейс трекинга в `TrackTask/TrackInterestPoint` + тост-момент. Паттерны:
    «условие-избегание» (эпизоды с гистерезисом, лимит = жалоба) и «точка интереса»
    (Succeeded трекингом, только State==Aboard).

**Репозиторий:**
16. Коммиты `Н8.<номер>: детально — compile EXIT 0`; не пушить; git-историю не
