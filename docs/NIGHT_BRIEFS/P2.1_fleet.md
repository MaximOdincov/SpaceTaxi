## ЗАДАЧА

Ввести «парк кораблей»: старт всегда на арендном «Яйце», покупка своих кораблей
(сам список купленных и владение), потеря корабля при гибели/потере с возвратом
на аренду. UI магазина будет в П3.2 — сейчас только модель и применение.

Правила (16_BETA_PLAN §3.1–3.3, НЕ менять числа):
- Старт новой игры: аренда «Яйца» (egg_rental), кредитов 0, долга 0.
- «Яйцо»-аренда всегда сток, не продаётся (Price 0, IsRental=true).
- Разбил/потерял арендный → получаешь НОВЫЙ арендный (тот же egg_rental) —
  долг за это добавляет П2.2 (сейчас просто продолжаешь на аренде).
- Разбил/потерял СВОЙ → теряешь его (вместе с будущими улучшениями), возврат
  на арендное «Яйцо».
- Покупка возможна только не-арендных (Price > 0) и ещё не купленных.

1. `Assets/Scripts/Economy/FleetService.cs` — plain C# (не MonoBehaviour),
   владелец GameSession (создаётся в Awake рядом с Wallet, публичное свойство
   только для чтения `Fleet`). API:
   - `ShipConfig Current` — текущий корабль (всегда валиден; при старте — egg_rental).
   - `IReadOnlyList<ShipConfig> OwnedShips` (владение: купленные модели).
   - `bool IsOwned(ShipConfig config)`.
   - `bool TryBuy(ShipConfig config, Wallet wallet)` — списывает Price через
     wallet.TrySpend, добавляет во владение и СРАЗУ пересаживает на купленный
     корабль (решение координатора: новый корпус = полные HP и полный бак,
     применяется мгновенно, пока корабль стоит на станции). Возвращает успех.
   - `void NotifyShipLost()` — текущий корабль потерян (гибель/потеря связи):
     если он был купленным — удалить из OwnedShips (улучшения слетают, их
     добавит П2.3), Current = egg_rental; если арендный — Current остаётся
     egg_rental. При этом корабль в мире должен продолжить работу с новым
     конфигом (см. п.2). Вызов — из GameSession по HullSystem.Died и
     HullSystem.ShipLost (подписка в Init-стиле GameSession; смотри, как
     OrderService подписывается на те же события — не дублировать логику,
     просто добавить ещё одного подписчика).
   - Событие `event Action ShipChanged` — для UI (П3+).
   - Арендный фолбэк — через `ShipConfig.EggRentalFallback` (уже есть в коде);
     если GameSession.currentShip в сцене указывает на kaban — для НОВОЙ игры
     парк всё равно стартует с арендного «Яйца» (поле сцены игнорируем; при
     желании можно оставить поле, но парк его не читает).
2. Смена конфига живого корабля: в `Assets/Scripts/Physics/Ship.cs` добавить
   `void Reconfigure(ShipConfig shipConfig)` — меняет Config/максимумы на ходу
   (HP и топливо при смене — ПОЛНЫЕ, новый корпус; смотреть, как Init берёт
   значения из ShipConfig и PhysicsConfig, и продублировать логику максимума;
   события FuelChanged/HpChanged должны уйти, чтобы HUD обновился). FleetService
   вызывает ship.Reconfigure через ссылку, переданную при Init (добавь
   `void BindShip(Ship ship)` или аргумент в метод — на твой вкус, но без
   FindAnyObjectByType внутри сервиса).
   Внимание: респавн HullSystem восстанавливает HP/топливо по текущему конфигу —
   проследи, что после смены конфига респавн использует НОВЫЙ MaxV/FuelMax/HpMax.
3. GameSession: `Fleet = new FleetService(...)` в Awake (старт: egg_rental,
   ни одного своего). WorldBuilder.Build продолжает собирать корабль по
   `fleet.Current` (не по полю сцены). Проверь совместимость с тем, что П1.2
   уже сделал (GameSession.CurrentShip → используется в Start).
