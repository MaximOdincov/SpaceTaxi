## ЗАДАЧА

Задания пассажиров — источник будущих чаевых. Универсального таймера НЕТ:
задание задаёт пассажир, одно на заказ, из его архетипа. ЭТА ЗАДАЧА: типы
«условия» (Барыга, Тихоня) и дедлайн (Торопыга). «Точки интереса» (Турист,
Чудик) — П8.1: у этих архетипов пока задание None.

1. `Assets/Scripts/Orders/PassengerTask.cs` — plain C# (ns SpaceTaxi.Orders):
   - `enum PassengerTaskKind { None, Deadline, NoRefuel, NoCollision, SpeedLimit }`.
   - Класс: `PassengerTaskKind Kind`, `string Text` (текст задания для карточки),
     `float DeadlineSeconds` (для Deadline), `float SpeedLimit` (для SpeedLimit),
     состояние `bool Succeeded`, `bool Failed` (внутреннее отслеживание).
2. Каталог заданий — статический в том же файле (тексты из §3.6, утверждены):
   - Торопыга → Deadline: T = дальность/150 + 45 с (дальность — полный маршрут
     заказа, RouteDistance; текст «Опаздываю! Доставьте меня за {0} с.»).
   - Барыга → NoRefuel «Не заправляемся в пути — станции пропускайте.»
     ИЛИ NoCollision «Бережёный груз: ни одного столкновения.» (случайный из двух).
   - Тихоня → SpeedLimit «Тише едем: не быстрее {0} юн/с весь полёт.» (лимит 250)
     ИЛИ NoCollision «Без трясок, пожалуйста.» (случайный).
   - Турист/Чудик → None (задания появятся в П8.1).
   Метод `PassengerTask Create(string archetype, float routeDistance)`.
3. Выдача: OrderService.AddOffer — задача создаётся вместе с оффером (нужна
   дальность — RouteDistance уже считается там), хранится в OrderOffer
   (поле `PassengerTask Task`; у существующих путей без задачи Kind == None).
   Таймер дедлайна: стартует в момент Accept (поле-время старта в задаче или
   в оффере), тикает только пока заказ Active/Aboard (в Update OrderService —
   он уже тикает офферы; пауза-безопасность: смотри фактический тайминг
   офферов и повтори подход).
   Провал дедлайна: время вышло до доставки → task.Failed = true (жалоба
   и без чаевых; заказ НЕ проваливается — доставка состояться может).
4. Отслеживание условий — период: пассажир НА БОРТУ (State == Aboard) до
   доставки/провала заказа:
   - NoRefuel: LandingSystem.StationServiced при Aboard → Failed.
   - NoCollision: LandingSystem.CrashImpact при Aboard → Failed
     (счётчик CollisionsOfActive П4.2 — отдельный механизм, не трогать).
   - SpeedLimit: скорость корабля (ship.Body.velocity.magnitude) > SpeedLimit
     хотя бы в одном кадре при Aboard → Failed.
   - Отслеживание ведёт OrderService в своём Update (у него уже есть ship
     и подписки; добавь подписку CrashImpact/StationServiced аккуратно —
     СМОТРИ фактический код: CrashImpact уже подписан П4.2 в OrderService
     для счётчика — добавь обработку задачи в ТОТ ЖЕ обработчик, не дублируй
     подписку).
5. Итог задания при доставке (в ветке Delivered):
   - Succeeded (условия не нарушены; дедлайн успели) → RatingService.TaskCompleted()
     (+0.10, сервис П4.3 уже есть у GameSession — передай OrderService Bind-методом,
     без FindAnyObjectByType) + тост успеха: фраза Thanks пассажира (стиль
     существующих тостов доставки).
   - Failed → Рейтинг НЕ растёт: вызови RatingService.TaskFailed() — НЕТ, в
     RatingService такого метода нет: добавь `void TaskFailed()` (−0.10,
     симметрично TaskCompleted; РЕШЕНИЕ координатора: жалоба пассажира =
     −0.10 по аналогии с таблицей §3.7) + тост-жалоба: фраза Complaints.
   - Чаевые НЕ начислять (П8.2).
6. UI карточек (OnboardBinder): на карточке оффера и в блоке активного заказа
   строка Wish теперь показывает ТЕКСТ ЗАДАНИЯ (task.Text при Kind != None;
   при None — как раньше из профиля). Для активного заказа с дедлайном —
   показывать остаток «Осталось {0} с» (обновление в SlowUpdate/RefreshOrder;
   < 15 с — красить в DangerColor, если константа доступна). Остальные строки
   не трогать.
