## ЗАДАЧА

SaveSystem: JSON в `Application.persistentDataPath/space_taxi_save.json`.
Автосейв при выходе в меню/из игры + при завершении заказа. Состав сейва —
§3.9: ресурс (кредиты), долги, счётчик аварий, рейтинг, доставки/провалы,
текущий корабль + купленные + улучшения, активный заказ (или отсутствие),
позиция/скорость/HP/топливо корабля, уровень (имя LevelAsset), настройки
(громкости УЖЕ в PlayerPrefs — в сейв не дублировать).

1. `Assets/Scripts/Core/SaveSystem.cs` — статический класс (ns SpaceTaxi.Core):
   - `[Serializable] SaveData` — плоские поля (никаких Unity-объектов):
     `string LevelName`, `int Credits`, `int DebtBalance`, `int UnpaidAccidents`,
     `float Rating`, `int Deliveries`, `int Failures`, `string CurrentShipId`,
     `string[] OwnedShipIds`, `Dictionary<string,int[]> UpgradeLevels`
     (или массив пар id+уровни — JsonUtility не умеет Dictionary: используй
     `[Serializable] class ShipUpgrades { string ShipId; int[] Levels; }`
     + List), `OrderSave ActiveOrder` (nullable-семантика: null/флаг HasOrder):
     `int PickupIndex, DropoffIndex, int Price, string TaskKind, float
     TaskDeadlineRemaining, bool TaskSucceeded, bool TaskFailed`, `string
     PassengerArchetype` (для восстановления фраз/задания — по факту П5.x),
     `ShipSave Ship` (`Vector2 Position, Vector2 Velocity, float Hp, float Fuel,
     bool Landed`), `string SavedAt` (ISO, для отладки).
   - `static void Save(GameSession session)` — собрать снапшот из фактических
     сервисов (через публичные API; если чего-то не хватает в API — ДОБАВЬ
     минимальное свойство-геттер, не лазь в приватные поля напрямую).
   - `static bool TryLoad(out SaveData data)` — чтение + JsonUtility.FromJson;
     кривой JSON/исключение/несовпадение LevelName с текущим LevelAsset →
     false, НИКАКИХ ошибок в лог (смотри §3.9 «кривой сейв = Продолжить неактивно»).
   - `static bool HasSave()` (без парсинга — просто File.Exists и непустой файл),
     `static void DeleteSave()`.
2. Автосейв: GameSession — при OrderDelivered (после выплаты/экрана — смотри
   фактический поток П4.2/П4.3: сейв ДО открытия экрана завершения или после
   закрытия — реши по потоку, главное консистентное состояние без двойного
   срабатывания) и при выходе в меню (SceneFlowButtons.LoadMainMenu и
   QuitGame — ТУТ ЖЕ Save перед загрузкой сцены; смотри фактический код —
   SaveSystem.Save(null-safe: если GameSession нет (в меню) — не сейвить).
   Увольнение (П2.2 Dismissal → кнопка «В МЕНЮ») — DeleteSave (§3.9/П10.2:
   сброс прогресса; координатор: сейв удаляется, «Продолжить» неактивно).
3. Восстановление: `static void ApplyTo(GameSession session)` — вызывается
   GameSession при старте сцены, ЕСЛИ включён режим «продолжить» (см. п.4):
   применяет кредиты/долг/рейтинг/счётчики (события рейтинга руками), владение
   + уровни (FleetService API — смотри фактический; если нет метода загрузки
   владения — добавь `RestoreState(...)`-метод БЕЗ обхода инкапсуляции),
   CurrentShipId → конфиг из каталога (каталог кораблей — смотри П3.2
   Resources-каталог; фолбэк egg_rental при кривом id), корабль: позиция/
   скорость/HP/топливо/состояние (Landed → посадка на планету индексом
   PickupIndex? НЕТ — планета, на которой стоял: добавь в ShipSave
   `int LandedPlanetIndex` при Landed=true и восстанови State/LandedOn
   через WorldBuilder-совместимый путь — смотри фактический респавн как
   референс; если посадка сложна — допустимо упрощение РЕШЕНИЕ: при Landed
   корабль ставится на поверхность той планеты, стоя (смотри, как
   HullSystem.RespawnAfter ставит корабль), при Flying — позиция+скорость
   как есть), активный заказ: восстановить оффер как Active (State Aboard,
   если пассажир на борту — смотри фактический порядок полей OrderOffer;
   задача пассажира — по TaskKind/остатку времени; если восстановление
   задачи нетривиально — РЕШЕНИЕ координатора: активный заказ можно
   НЕ восстанавливать при упрощении, но тогда В ОТЧЁТЕ явно: «активный
   заказ теряется при загрузке» — постарайся восстановить, это §3.9).
4. Режим «продолжить»: `SaveSystem.ConsumeContinueFlag()` — статический флаг
   bool (ставится SceneFlowButtons.ContinueGame ПЕРЕД загрузкой сцены,
   снимается после чтения). GameSession.Start: если флаг и TryLoad успешен —
   ApplyTo после сборки мира (порядок: мир построен по дефолту → применить
   состояние). NewGame — флаг не ставится, сейв игнорируется (но не удаляется).
