## ЗАДАЧА

Улучшения 4 линии × 3 уровня, только на КУПЛЕННЫЕ корабли (аренда всегда сток).
Данные в SO, эффекты применяются к полёту/корпусу, сброс при потере корабля.
UI покупки будет в П3.3 — сейчас модель и применение.

Правила (16_BETA_PLAN §3.4, числа НЕ менять):
- Цены за уровень: 300 / 700 / 1500 (ур. 1/2/3).
- Эффекты растут линейно (ур.1 = ⅓, ур.2 = ⅔, ур.3 = максимум):
  - Двигатель: тяга +25%, буст качели 1.15 → 1.30 (линейно, ур.3 = 1.30)
  - Бак: ёмкость +60%, расход −15%
  - Корпус: HP +60%, жар-защита +30%
  - Манёвровые: боковая тяга +35%
- MaxV улучшениями не меняется.
- Полная прокачка корабля = 4 × 2500 = 10000.
- Разбил свой → теряешь корабль И улучшения (сброс).

1. `Assets/Scripts/Economy/UpgradeConfig.cs` — ScriptableObject
   (CreateAssetMenu "Space Taxi/Upgrade Config"), ns SpaceTaxi.Economy:
   - `enum UpgradeLine { Engine, Tank, Hull, Maneuver }` (в этом же файле).
   - `int[] PricesPerLevel = { 300, 700, 1500 }` (индекс = уровень−1).
   - Русские отображаемые имена линий (для П3.3): `EngineName = "Двигатель"`,
     `TankName = "Бак"`, `HullName = "Корпус"`, `ManeuverName = "Манёвровые"`.
   - Максимальные эффекты (ур.3): `EngineThrustPct = 25`, `EngineBoostMax = 1.30`,
     `TankCapacityPct = 60`, `TankDrainRedPct = 15`, `HullHpPct = 60`,
     `HullHeatRedPct = 30`, `ManeuverStrafePct = 35`.
   - Ассет `Assets/ScriptableObjects/UpgradeConfig_Default.asset` с этими
     значениями — создать YAML-файлом (паттерн — ассеты Ships/*.asset) либо
     кодом, значения должны читаться в инспекторе. Не забыть .meta для .cs —
     их сгенерирует компиляция координатора, ты их не создаёшь.
2. `Assets/Scripts/Economy/ShipStats.cs` — статик-хелпер: структура
   `EffectiveStats` (Thrust, Strafe, FuelMax, HpMax, FuelDrain, GravityBoost,
   HeatMul) и метод `Compute(PhysicsConfig, ShipConfig, int[] levels,
   UpgradeConfig)` — линейная интерполяция от уровней (levels[0..3] для линий
   Engine/Tank/Hull/Maneuver; 0 = нет улучшения). Base GravityBoost и FuelDrain —
   из PhysicsConfig. Никакого состояния, чистая функция.
3. Хранение уровней: в `FleetService` (фактический код П2.1) —
   `Dictionary<string, int[]>` по `ShipConfig.Id`, приватно. API:
   - `void BindUpgrades(UpgradeConfig cfg)` — конфиг (вызывает GameSession в Awake).
   - `int GetLevel(ShipConfig, UpgradeLine)`.
   - `bool TryUpgrade(ShipConfig, UpgradeLine, Wallet)` — только на купленный
     (`IsOwned`, аренда всегда false), уровень < 3, стоимость
     `PricesPerLevel[level]` через wallet.TrySpend; успех → уровень +1,
     событие `event Action UpgradesChanged` и пересадка НЕ происходит, но
     живой корабль должен пересчитаться (см. п.4 — Reconfigure дергает
     вызывающий код через BindShip-ссылку; решай по факту, где удобнее —
     главное без циклических зависимостей Economy→Physics).
   - При потере корабля (ветка NotifyShipLost с удалением из owned) — запись
     уровней удаляется (сброс). Рефакторить П2.1-логику можно минимально.
4. Применение к кораблю:
   - `Ship.Reconfigure` расширить уровнями: `void Reconfigure(ShipConfig,
     int[] upgradeLevels)` (старый однопараметровый вызов сохранить как
     делегирование с null). Ship хранит `int[] UpgradeLevels` и публичное
     `EffectiveStats Eff` (пересчёт через ShipStats.Compute; при null
     upgradeLevels/конфига — нулевые уровни, т.е. базовые статы).
   - ShipController: тяга/стрейф/расход/буст качели — из `ship.Eff`
     (сейчас читает ShipConfig/PhysicsConfig напрямую — заменить на
     эффективные значения; формулы физики НЕ менять, только источники чисел).
   - HullSystem.ApplyHeat: урон от жара × `ship.Eff.HeatMul` (жар-защита).
   - FuelMax/HpMax уже берутся из ShipConfig в нескольких местах (смотри
     фактический код П1.2/П2.1: Ship.Init/Reconfigure, HullSystem респавн,
     LandingSystem) — везде подставить Eff-значения там, где это максимум
     корабля (аккуратно: LandingSystem заправляет `Fuel = FuelMax` — теперь
     Eff.FuelMax; не сломать подписки FuelChanged/HpChanged).
5. GameSession: создание UpgradeConfig-ссылки: `[SerializeField] UpgradeConfig
   upgradeConfig` (в сцене пока не назначен — фолбэк: если null, использовать
   инстанс с дефолтными значениями, созданный кодом один раз — паттерн
   EggRentalFallback; никаких NRE). После TryUpgrade (будет из П3.3) —
   Reconfigure с новыми уровнями.
