## ЗАДАЧА

### Часть A — таблица
Собрать `SpaceTaxiUnity/GameInfo/BALANCE_N3.xlsx` (openpyxl) — ЕДИНСТВЕННЫЙ
источник баланса. Требования владельца:
- **Всё на формулах Excel** (не значения): изменение одного входа пересчитывает
  все зависимые метрики. Входные ячейки выделены заливкой (жёлтая = вход).
- **Условное форматирование**: красный = проблема (недостижимо/не окупается/
  смерть без шанса), жёлтый = пограничное, зелёный = норм.
- Листы:
  1. **СВОДКА** — целевые ориентиры и главные выводы (формулами из других листов).
  2. **КОРАБЛИ** — по строке на модель: тир, цена, тяга, манёвр, MaxV, бак, HP,
     Retro, габарит. Расчётные колонки (формулы):
     - время разгона до MaxV = MaxV/Thrust (с);
     - тормозной путь с MaxV до LandSpeed = (MaxV²−LandSpeed²)/(2·Retro);
     - запас хода (юниты) = FuelMax/FuelDrain × средняя скорость
       (средняя скорость = 0.6×MaxV — константа на листе, вход);
     - заказов на бак = запас хода / средняя длина заказа;
     - доход за заказ (от листа ЭКОНОМИКА: база+дистанция × сектор × тир-множитель
       премиальности + чаевые × шанс выполнения задания);
     - расход на заказ (топливо × цена топлива тира заправки);
     - чистый доход/заказ; **окупаемость покупки = Δцена / Δчистый доход**
       (заказов до окупаемости относительно предыдущего тира);
     - выживаемость = HP / средний урон за заказ.
  3. **УЛУЧШЕНИЯ** — линии Engine/Tank/Hull/Maneuver: цена уровня → прирост стата
     → эффект на те же метрики → окупаемость уровня в заказах.
  4. **ЭКОНОМИКА** — BasePrice, цена/юн, кап дистанции, множители секторов
     (Hub/Near 1.0, Mid1 1.3, Mid2 1.6, Far 2.0), множитель премиальности ТИРА
     корабля (вход! предлагается 1.0/1.05/1.1/1.2/1.3 по тиру), чаевые
     (TipsPct), шанс задания и бонус его выполнения, скейл рейтинга
     (порог 4.0 → +10%, <2.0 → спавн ×1.3), штраф за столкновение (15%/кап 45%),
     комиссия аренды (25%), цена топлива по тир сети (1.0/70%...1.8/100%),
     ремонт (пакеты, лимит визита), долг (400) и доля погашения (50%).
  5. **СЦЕНАРИИ** — 4 стратегии, по формулам: (а) «всё купить + всё улучшить»,
     (б) «копить на Барина на аренде» (антипаттерн — должен быть ВЫГОДНЕЕ
     прогрессии, см. ниже), (в) «все корабли без улучшений», (г) «4-5 кораблей
     + пара улучшений». Для каждой: суммарное время (заказы × время заказа +
     покупки), число заказов, финальный корабль. Сценарий (б) должен быть
     ХУЖЕ (дольше/скучнее) сценария (г) — если нет, крутить входы.
- Целевые инварианты (формулами или ручными входами, проверяемые условным
  форматированием):
  - каждый переход на следующий тир окупается за **6-10 заказов**;
  - аренда-«Яйцо» даёт чистый доход > 0, но худший в тире;
  - бак слабого корабля = **1.5-2 заказа**, сильного = **3-5**, Барина — 5+;
  - тормозной путь сильного корабля короче слабого (ретро растёт с тиром);
  - время полного прохождения по сценарию (г) = **30-35 мин**;
  - смерть от полного врезания в планету — гарантирована для всех корпусов
    (урон ≥ HP на максималке).

### Часть B — применение
Посчитать финальные числа и применить в ассеты (yaml правится руками аккуратно
или editor-скриптом): ShipConfig (Price/Thrust/MaxV/FuelMax/HpMax/Retro),
UpgradeConfig (PricesPerLevel/проценты), PricingConfig (BasePrice,
PricePerDistanceUnit, сектор-множители), DebtService (долг). **Логировать
«параметр: было → стало → почему»** (каждая строка). Ретюнить ТОЛЬКО числа,
не формулы. Если какое-то целевое требование владельца требует изменения
ФОРМУЛЫ (например, множитель премиальности тира в оплате — его в коде НЕТ) —
добавить минимально: PricingConfig поле `TierPrestigeMul` (5 значений по тиру)
+ применение в OrderPricing.ComputePrice — отметить в логе как изменение
механики.
Подсказки по направлению (не догма — таблица главнее):
- цена/юн или база растут, чтобы переходы окупались за 6-10 заказов;
- FuelMax: egg ~140, скрепка ~150, стрела ~170, дельта ~190, кабан ~220,
  меридиан ~230, игла ~210, барин ~300 (проверить таблицей);
- Retro: уже 60-75 по тиру — проверить тормозным путём (цель: торможение с
  MaxV за ≤ 350-450 юнитов);
- цены кораблей пересчитать от дохода/заказ (окупаемость 6-10 заказов).
